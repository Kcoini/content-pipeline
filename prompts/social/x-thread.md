# x 프롬프트 (thread)

## platform 목적
짧은 후킹 문장으로 시작해 여러 개의 짧은 트윗(thread_items)으로 정보를
전달한다. X는 글자 수 제한이 엄격하고 스크롤 중 즉시 시선을 끌어야
한다.

## 독자 특성
타임라인을 빠르게 스크롤하는 독자. 첫 문장(hook)에서 멈추지 않으면
바로 지나친다.

## 글 길이 기준
`preferredLength=short`, 트윗 1개당 최대 280자, 최소 20자.

## 허용 필드
`thread_items`(필수, 순서가 있는 배열), `post_body`(선택, 단일 트윗만
쓸 경우), `hashtags`(선택, 2개 내외 권장). `post_title`/`caption`/
`card_items`는 사용하지 않는다.

## 금지 표현
공통 금지 표현 + **낚시성/과장 표현** 금지(내용과 무관한 충격적 단어로
클릭만 유도하는 것 금지).

## 출력 JSON 형식
```json
{
  "thread_items": [
    { "order": 1, "text": "후킹 문장 (첫 트윗)" },
    { "order": 2, "text": "두 번째 트윗" }
  ],
  "hashtags": ["키워드"],
  "platform_metadata": { "includesLink": false }
}
```

## 구조 원칙
- 각 thread item은 **짧고 명확하게** — 한 트윗에 하나의 아이디어만
  담는다.
- 첫 트윗은 반드시 후킹(hook) 역할을 해야 한다 (질문, 반전, 놀라운
  사실 등 — 단 낚시성/과장은 금지).
- 마지막 트윗은 요약 또는 행동 유도(부드러운 방식)로 마무리할 수 있다.

## 링크 포함 여부
링크를 실제로 포함할지 여부는 `platform_metadata.includesLink`로
관리한다 — 이 프롬프트 자체가 임의로 링크를 본문에 삽입하지 않는다.

## tone_style 반영 방식
`prompts/tones/*.md` 가이드를 따르되, 트윗 특성상 문장을 최대한 압축한다.

## 실행 전제
**dry-run 전제**다 — 실제 X API 게시 연동은 하지 않는다.

## 승인/출처 원칙
- 사람이 승인하기 전에는 게시하지 않는다.
- 출처에 없는 사실을 단정하지 않는다.
- 원문 기사를 그대로 복사하지 않는다.
