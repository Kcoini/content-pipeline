# opinion_column 프롬프트

## platform 목적
관점과 해석이 중심인 의견형 글(칼럼)이다. 마스터 원고(구조화된 편집
자료)를 바탕으로, 특정 주제에 대한 명확한 관점을 세우고 근거로
뒷받침한 뒤 반론/한계까지 다루는 칼럼을 만든다. news_article과
정반대로, "중립적 사실 전달"이 아니라 "관점을 설득력 있게 전달하는
것"이 목적이다. opinion_column은 마스터 원고 자체가 아니라, 마스터
원고를 바탕으로 생성되는 플랫폼별 출력물 중 하나다.

## 독자 특성
특정 주제에 대해 다른 사람은 어떻게 보는지 궁금한 독자. 사실 나열보다
"왜 그렇게 생각하는지"와 "그래서 어떤 의미인지"를 원한다.

## 글 길이 기준
`preferredLength=medium`, 최소 500자 ~ 최대 3500자.

## 구조
1. 제목 — 관점이 드러나되 단정적 비방으로 흐르지 않는다.
2. 문제 제기 — 왜 이 주제를 다루는지.
3. 중심 관점 — 글쓴이가 주장하는 핵심 관점 하나를 명확히 밝힌다.
4. 근거 — 그 관점을 뒷받침하는 사실/사례(마스터 원고의
   `factInterpretationSplit`에서 사실과 해석을 구분해 가져온다).
5. 해석 — 그 사실이 왜 중심 관점을 뒷받침하는지 설명한다.
6. 반론 또는 한계 — 다른 시각이나 이 관점의 한계를 인정한다(생략
   금지 — 칼럼에 반드시 필요하다).
7. 결론 — 중심 관점을 다시 정리한다.

## 허용 필드
`post_title`(필수), `post_body`(필수, 위 구조를 담은 본문),
`excerpt`(선택, 한 줄 요약). `caption`/`hashtags`/`thread_items`/
`card_items`는 사용하지 않는다.

## 문체 원칙
- **관점이 명확**해야 한다 — 이 글이 의견형(칼럼)임이 드러나야 한다.
- **사실과 의견을 구분**한다: "이는 확인된 사실이다"와 "이는 필자의
  해석이다"를 문장으로 구분해 표시한다.
- **반론/한계를 반드시 포함**한다 — 한쪽 주장만 일방적으로 펼치지
  않는다.
- 과도한 단정이나 비방 표현을 쓰지 않는다.
- 뉴스 기사처럼 중립을 가장하지 않는다(관점이 있는 글임을 숨기지
  않는다).

## 금지 표현
공통 금지 표현 + 다음을 특히 금지한다.
- 사실인 것처럼 위장한 단정적 의견
- 근거 없는 비방/인신공격
- 광고 클릭 유도
- "무조건", "틀림없이" 같은 과도한 단정
- 반론/한계를 생략한 일방적 주장

## 자동 검토 시 특히 확인할 것
- 관점이 명확한가
- 사실과 의견이 구분되는가
- 근거가 있는가
- 반론 또는 한계가 있는가
- 과도한 단정이나 비방이 없는가
- 칼럼형 글임이 명확한가

## 출력 JSON 형식
```json
{
  "post_title": "제목",
  "post_body": "문제 제기 → 중심 관점 → 근거 → 해석 → 반론/한계 → 결론 순서로 구성된 칼럼 본문",
  "excerpt": "한 줄 요약 (선택)",
  "platform_metadata": {}
}
```

## Export 전제
이 플랫폼도 다른 플랫폼과 마찬가지로 **manual export 전제**다 —
자동 게시 API 연동은 하지 않으며, 사람이 최종 승인한 뒤 직접
게시(또는 배포)한다.

## 승인/출처 원칙
- 사람이 승인하기 전에는 게시하지 않는다.
- 출처에 없는 사실을 단정하지 않는다.
- 원문 기사를 그대로 복사하지 않는다.
