====================================================================
content-pipeline 사용법
====================================================================

이 문서는 content-pipeline 프로젝트를 처음 사용하는 사람을 위한
안내문이다. 개발 환경 설정부터 기사 생성, 여러 플랫폼용 글쓰기,
검수/승인, 게시 준비, 성과 확인까지 실제로 화면에서 클릭하는
순서를 기준으로 정리했다.

--------------------------------------------------------------------
1. 이 프로젝트가 하는 일
--------------------------------------------------------------------

content-pipeline은 아래 순서로 동작하는 콘텐츠 자동 생성/운영
파이프라인이다.

  주제 입력
    -> 출처 등록
    -> 계약 검사
    -> 기사 초안 생성(draft)
    -> AI 품질 평가
    -> 사람의 승인(reviewed)
    -> 여러 플랫폼용 글로 재작성
    -> 검수/승인
    -> 수동 게시 준비(export / guard / dry-run / handoff)
    -> 사람이 직접 각 플랫폼에 게시
    -> 게시 결과 및 성과 수동 입력
    -> 성과 기반 재작성(rewrite) 및 비교
    -> 대시보드에서 전체 현황 확인

중요: 이 파이프라인은 "생성"과 "게시 준비"까지는 자동으로 도와주지만,
실제로 외부 플랫폼(블로그, SNS 등)에 글을 올리는 마지막 동작은
항상 사람이 직접 수행한다. 자동으로 실제 게시가 이루어지는 기능은
없다.

--------------------------------------------------------------------
2. 개발 환경 설정
--------------------------------------------------------------------

1) 의존성 설치
   npm install

2) 환경변수 설정
   프로젝트 루트에서 아래 명령으로 .env.local 파일을 만든다.
     cp .env.example .env.local
   .env.local 파일을 열어 필요한 값(Supabase URL/Key,
   ANTHROPIC_API_KEY 등)을 채워 넣는다.
   주의: .env.local 파일은 절대 git에 커밋하지 않는다
   (.gitignore에 이미 등록되어 있다).
   전체 환경변수 이름과 용도는 아래 문서를 참고한다.
     docs/environment-variables.md (Phase 1~2 관련)
     docs/phase-3-environment-variables.md (Phase 3 관련)

3) DB 스키마 적용
   Supabase 프로젝트의 SQL Editor에서 db/schema.sql을 실행하고,
   이어서 db/migrations/ 폴더의 SQL 파일들을 순서대로(파일명 앞
   번호 순서대로) 실행한다.

4) 개발 서버 실행
   npm run dev
   브라우저에서 http://localhost:3000 접속

3. 기본 사용 순서 (기사 한 편 만들기)
--------------------------------------------------------------------

[1] /dashboard 접속
    - 새 테마(주제) 입력, 또는 "자동 테마 찾기"로 트렌드 기반 주제
      탐색
    - 주제별로 출처(참고 URL) 3개 이상 등록

[2] 계약 검사 통과 확인
    - 출처가 3개 미만이면 기사 생성이 시작되지 않는다

[3] 기사 초안 생성
    - "기사 초안 생성" 버튼 클릭 -> AI가 초안을 만들고 자동으로
      품질 평가(AI Evals)를 실행한다
    - 결과는 항상 화면에 표시된다

[4] 기사 검토 및 승인
    - 초안 내용을 확인하고 필요하면 수정
    - 승인 버튼을 눌러야 상태가 draft -> reviewed로 바뀐다
      (자동 승인 없음)

--------------------------------------------------------------------
4. 여러 플랫폼용 글쓰기 (Phase 3)
--------------------------------------------------------------------

승인된 기사를 기반으로 플랫폼별 글을 만든다.

[1] /articles/[id] 접속
    - 기사 개요 확인, 하위 메뉴(블로그/소셜/재작성/성과/A-B테스트)
      진입

[2] /articles/[id]/blog
    - 블로그형 플랫폼(WordPress Blog, Naver Blog)용 글 관리

[3] /articles/[id]/social
    - SNS/커뮤니티형 플랫폼(Naver Cafe, X, Threads, Instagram)용
      글 관리

    지원 문체(tone): 설명형(explanatory), 정보전달형(informational),
    설득형(persuasive), 경고형(warning), 손실회피형(loss_aversion),
    호기심유발형(curiosity), 비교형(comparison), 스토리텔링형(story)

[4] 각 글(social post)마다 아래 순서로 버튼을 누른다
    1. 초안 생성
    2. 품질검사
    3. 승인 요청 -> 승인
    4. Manual Export (복사용 게시 자료 생성)
    5. Publishing Guard 실행 (금지 표현 등 최종 점검)
    6. Dry-run 생성 (실제 게시 없이 최종 형태 미리보기)
    7. Handoff 완료 (게시 담당자에게 넘길 준비 완료 표시)

[5] 사람이 실제 플랫폼에 직접 게시
    - export 자료와 dry-run 결과를 참고해 WordPress 관리자 화면,
      X/Threads/Instagram 앱, Naver Blog/Cafe 등에 직접 게시한다
    - 이 단계는 자동화되어 있지 않다

[6] 게시 후 기록
    - "게시 결과 기록" 버튼으로 실제 게시 URL/결과 입력
    - "Metrics 입력" 버튼으로 조회수, 좋아요, 댓글, 공유 등을
      직접 입력 (자동 수집 아님)

--------------------------------------------------------------------
5. 성과 확인 및 재작성(rewrite)
--------------------------------------------------------------------

[1] /articles/[id]/performance
    - 입력한 metrics를 바탕으로 성과 점수 확인

[2] /articles/[id]/rewrite
    - 성과가 낮은 글에 대해 재작성 제안 생성
    - 제안을 적용하면 원본을 덮어쓰지 않고 새 버전으로 저장된다
    - 새 버전은 재승인을 거쳐야 다시 export할 수 있다
    - 원본과 재작성본의 실제 성과를 비교할 수 있다

[3] /articles/[id]/ab-tests
    - 원본과 재작성본 등을 묶어 A/B 테스트 초안을 만든다
    - 자동으로 실행되거나 승자가 자동 결정되지 않는다
      (수동 입력 metrics를 바탕으로 비교만 제공)

--------------------------------------------------------------------
6. 대시보드로 전체 현황 확인
--------------------------------------------------------------------

  /dashboard                     : 기본 대시보드(테마/출처/기사 생성)
  /dashboard/content              : 기사 단위 전체 콘텐츠 현황
  /dashboard/blog                 : 블로그형 글 전체 현황
  /dashboard/rewrite              : 재작성 워크플로우 현황
  /dashboard/social-performance   : 플랫폼/문체별 성과, 차트
  /dashboard/platform-api         : 플랫폼별 API 게시 "준비 상태"만
                                     확인 (실제 게시 버튼 없음)
  /dashboard/automation-safety    : 자동화 안전 점검 결과 확인
                                     (점검 전용, 데이터 수정 없음)

--------------------------------------------------------------------
7. 반드시 알아야 할 안전 원칙
--------------------------------------------------------------------

- 실제 외부 플랫폼에 자동으로 게시하는 기능은 없다
  (WordPress draft 생성만 예외이며, 이것도 "초안" 상태일 뿐
  공개 게시가 아니다)
- 승인되지 않은 글은 export/게시 준비 단계로 진행할 수 없다
- 재작성(rewrite)은 항상 새 글로 저장되며 원본을 덮어쓰지 않는다
- 성과 수치(metrics)는 전부 사람이 직접 입력한 값이다
  (자동 수집 아님)
- API 키, 토큰, 비밀번호 값은 화면이나 로그, 문서 어디에도
  노출되지 않는다
- /dashboard/automation-safety 에서 위 원칙들이 실제로 지켜지고
  있는지 언제든 점검할 수 있다
