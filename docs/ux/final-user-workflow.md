# 최종 제품 사용자 흐름

기술 구현이 아니라 실제 사용자가 화면에서 겪는 순서로 정리한 문서다.
플랫폼별 세부 차이는 마지막 절을 참고한다.

## 1. 테마 선택

`/dashboard`(또는 `/trends`)에서 자동 추출된 테마 후보를 확인하고 하나를
선택한다. 신규/기존 업데이트/중복/확인 필요로 이미 분류되어 있어
"선택 불가"로 끝나는 후보가 없다.

## 2. 자료 수집

선택한 테마에 출처(URL)를 최소 3개 등록한다. 등록 폼은 기본 접힘이라
목록/다음 작업이 폼에 가려지지 않는다.

## 3. 글 만들기

마스터 원고(article)를 생성한다. 이어서 플랫폼별 글(WordPress
블로그/네이버 블로그·카페/뉴스 기사/X/Threads/Instagram)을 필요한
것만 선택해 생성한다 — "전체 생성"은 고급 옵션 뒤에 숨겨져 있고 실행
전 확인을 거친다.

## 4. 필요한 내용만 확인

자동 검토가 먼저 실행된다. AI가 안전하게 고칠 수 있는 문제(auto_fixable)는
자동으로 정리·재검토되고, 사람은 사실 확인이 필요한 문제(출처/수치/
날짜 등)만 확인하면 된다. "통과/확인 필요/수정 필요/차단" 중심으로
요약되며 raw 상태값은 보이지 않는다.

## 5. 승인

확인이 끝나면 승인 버튼을 누른다. 승인은 실제 게시가 아니라 "이 내용을
게시 준비 단계로 넘긴다"는 뜻이다. 승인 완료 후에는 승인 버튼이 다시
나타나지 않고, 플랫폼에 맞는 다음 작업 버튼이 나타난다.

## 6. 게시 준비

플랫폼마다 실제로 가능한 준비 작업만 안내한다(이 프로젝트는 실제
외부 공개 게시 API를 호출하지 않는다):

- **WordPress**: Draft를 만든다(공개 게시 아님).
- **네이버 블로그/뉴스 기사**: 수동 게시 준비 자료(체크리스트)를
  만든다.
- **네이버 카페/X/Threads/Instagram**: 게시용 본문을 복사한다.

## 7. WordPress Draft 또는 본문 복사

6번에서 만든 결과를 실제로 사용하는 단계다. WordPress는 만들어진
Draft를 워드프레스 관리자 화면에서 직접 확인·공개 게시한다(이 앱은
Draft 생성까지만 담당). 그 외 플랫폼은 복사한 본문을 해당 플랫폼에
직접 붙여넣어 게시한다.

## 8. 수동 게시 완료 기록

실제로 게시를 마쳤으면 "게시 완료로 표시"를 눌러 기록한다. 복사만으로는
게시 완료로 기록되지 않는다 — 반드시 이 단계를 명시적으로 거쳐야
"게시 완료" 상태가 된다.

---

## 플랫폼별 차이 요약

| 플랫폼 | 게시 준비 결과 | 완료 판정 |
| --- | --- | --- |
| WordPress 블로그 | Draft 생성 | Draft 생성까지가 이 앱의 역할(공개 게시는 WordPress 관리자에서 직접) |
| 네이버 블로그/뉴스 기사 | 수동 게시 준비 자료(체크리스트) | 사용자가 "게시 완료로 표시"를 눌러야 완료 |
| 네이버 카페 | 게시용 본문 복사(markdown 잔여물 자동 정리) | 복사만으로는 완료 아님, "게시 완료로 표시" 필요 |
| X (thread) | 스레드 전체 복사 | 게시 완료 후에는 재수정이 차단됨 |
| Threads / Instagram | 게시용 본문/캡션 복사 | "게시 완료로 표시" 필요 |

어느 플랫폼도 이 프로젝트 안에서 "버튼 한 번으로 외부에 즉시
공개 게시"되지 않는다 — 항상 사람이 마지막 단계를 직접 확인하고
실행한다.
