# 사용설명서 (User Guide)

이 문서는 content-pipeline을 실제로 사용하는 사람을 위한 사용설명서다.
각 단계가 화면에서 어떻게 보이는지, 어떤 버튼을 누르면 되는지, 그리고
**왜 그 단계가 필요한지**를 함께 설명한다.

## 이 프로그램이 하는 일

주제 하나를 정하면 → 관련 출처를 모으고 → AI가 기사 초안을 쓰고 →
사람이 검토·승인하고 → WordPress에 초안을 올리고 → SEO/대표 이미지를
갖추고 → 여러 단계의 자동 검증을 통과한 뒤 → **사람이 마지막으로 승인한
경우에만** 실제로 블로그에 공개한다.

### 왜 이렇게 단계가 많은가

이 프로그램은 "AI가 알아서 블로그에 글을 자동으로 올려주는 도구"가
**아니다**. 오히려 정반대에 가깝다 — AI가 만든 초안이 실제로 공개돼도
괜찮은 품질인지 여러 겹으로 확인하고, **사람이 명시적으로 승인 버튼을
누르기 전까지는 어떤 글도 공개(publish)되지 않도록** 설계되어 있다.
그래서 검증 단계가 많아 보이지만, 각 단계는 "이거 하나라도 빠지면
문제가 될 수 있는 것"을 담당한다:

- 출처가 부족한 글이 나가는 것을 막는다 (신뢰성)
- SEO 정보 없이 발행되는 것을 막는다 (검색 유입)
- 대표 이미지 없이 발행되는 것을 막는다 (수익형 블로그의 경우 광고 승인/체류시간에 영향)
- 광고 클릭 유도 문구, 저작권 위험, 개인정보 노출 같은 위험 요소를 사전에 걸러낸다
- 마지막으로, **사람이 실제로 확인하고 승인 버튼을 눌렀는지**를 반드시 거치게 한다

## 전체 흐름 한눈에 보기

```
[테마 만들기] → [출처 등록] → [기사 초안 생성] → [기사 검토/수정] → [기사 승인]
      ↓
[WordPress metadata 생성] → [SEO plugin metadata 생성]
      ↓
[대표 이미지 정보 준비] → [(선택) 이미지 생성] 또는 [대표 이미지 Source 설정]
      ↓
[WordPress 연결 테스트] → [WordPress 초안 생성]
      ↓
[WordPress Media Upload] → [Featured Media Attach]
      ↓
[SEO Plugin 실제 반영 / Rank Math custom endpoint]
      ↓
[Final Draft Review] → [Publish Quality Gate] → [Human Approval] → [WordPress 공개 게시 테스트]
      ↓
[WordPress 관리자에서 최종 확인]
```

위에서 아래로 순서대로 진행하면 되고, 앞 단계를 건너뛰면 다음 단계
버튼이 비활성화되거나 "먼저 OO를 실행하세요" 안내가 뜬다.

---

## 1단계. 테마 만들기

**화면**: 대시보드(`/dashboard`) 왼쪽 사이드바

**방법 두 가지**:
- **수동 생성**: 제목/설명/키워드/언어를 직접 입력하고 "테마 생성" 버튼
- **트렌드 기반 자동 추출**: "자동 테마 찾기"(`/trends`) 페이지에서 "트렌드
  수집 + 공통 테마 추출 실행" 버튼 → 여러 플랫폼(네이버/다음)의 트렌드
  키워드를 모아 공통 주제를 클러스터링해 보여줌 → 마음에 드는 클러스터의
  "이 테마로 기사 작성 시작 →" 버튼

**왜 필요한가**: 기사는 반드시 하나의 "주제(theme)"에 속해야 한다. 주제가
없으면 어떤 출처를 모아야 할지, 어떤 기사를 써야 할지 방향을 잡을 수
없다. 트렌드 기반 추출은 "지금 사람들이 많이 찾는 주제"를 반영해 검색
유입 가능성을 높이기 위한 옵션이다.

## 2단계. 출처 등록

**화면**: 대시보드에서 선택한 테마 아래 "출처 추가" 폼, 또는
`/themes/[themeId]`의 "관련 기사 URL 후보 수집" → 체크박스로 선택 후
"선택한 후보 출처 등록"

**왜 필요한가**: AI가 근거 없이 글을 지어내는 것(hallucination)을
막기 위해서다. **출처가 3개 미만이면 기사 생성 자체를 시작할 수 없다**
(`contracts/source.contract.yaml`에 정한 규칙). 출처 URL을 자동으로
가져와 본문/발행일/요약을 채워주므로, 최소한의 사실관계를 AI에게
전달할 수 있다.

## 3단계. 기사 초안 생성

**화면**: 대시보드의 "글쓰기 모드" 라디오 버튼(일반 기사형 /
출처 기반 설명형 / 수익형 블로그형) 선택 후 "기사 초안 생성"

**왜 필요한가**: 글의 목적에 따라 요구되는 요소가 다르다. 예를 들어
수익형 블로그형은 광고 슬롯(AD_SLOT)과 SEO metadata가 반드시 필요하지만
일반 기사형은 그렇지 않다. 모드를 먼저 선택해야 이후 단계(SEO/이미지/
Quality Gate)의 기준이 올바르게 적용된다. 생성된 기사는 항상
`status='draft'`로 저장되며, 이 상태에서는 아직 아무 곳에도 공개되지
않는다.

## 4단계. 기사 검토/수정

**화면**: article 상세 페이지의 본문 영역, "수정 내용 저장" 버튼
(draft 상태에서만 수정 가능)

**왜 필요한가**: AI가 쓴 초안을 그대로 내보내지 않고, 사람이 사실관계·
문체·오탈자를 검토하고 고칠 기회를 준다. `reviewed` 상태로 넘어가면
더 이상 본문을 수정할 수 없으므로, 이 단계에서 확실히 다듬어야 한다.

## 5단계. 기사 승인

**화면**: "승인하기" 버튼 (draft 상태에서만 노출)

**왜 필요한가**: `status`를 `draft → reviewed`로 바꾸는 것은 "이 글
내용에 문제없다"는 사람의 명시적 의사표시다. 이후 모든 WordPress 관련
작업(초안 생성, 이미지 업로드 등)은 `reviewed` 상태를 전제로 동작한다.

## 6단계. WordPress metadata 생성

**화면**: "WordPress metadata 생성" 버튼 → category/tag/SEO title/meta
description/slug/target keyword/secondary keywords/internal link
제안/광고 슬롯 자동 생성 → "metadata 검토 완료" 버튼

**왜 필요한가**: WordPress에 글을 올리려면 카테고리·태그·SEO 정보가
필요하다. 이 정보 없이 발행하면 검색엔진에 제대로 노출되지 않거나
분류가 안 된 글이 된다. `target_keyword`는 이후 SEO plugin 반영과
Quality Gate 판정에서 계속 사용되는 핵심 값이다.

## 7단계. SEO Plugin metadata 생성

**화면**: "SEO plugin metadata 생성" 버튼 (Yoast/Rank Math/AIOSEO 중
설정된 provider 기준)

**왜 필요한가**: WordPress metadata(6단계)는 워드프레스 기본 필드이고,
실제 검색 노출에 큰 영향을 주는 것은 SEO plugin(Rank Math 등)이 사용하는
전용 메타 필드다. 이 단계는 그 필드에 넣을 값을 미리 준비한다(아직
WordPress에 실제로 쓰지는 않음 — 실제 반영은 15단계).

## 8단계. 대표 이미지 정보 준비 (선택)

**화면**: "대표 이미지 정보 준비" 버튼 → prompt/alt text/caption/style
생성 → "검토 완료"

**왜 필요한가**: 실제 이미지를 만들거나 고르기 전에, "어떤 이미지가
필요한지"에 대한 설명(alt text 등 접근성 정보 포함)을 먼저 정리해 두면
이후 이미지 생성이나 대체 텍스트 작성이 수월해진다. 이 단계 자체는 선택
사항이며 건너뛰어도 게시를 막지 않는다.

## 9단계. 이미지 생성 (선택, AI 연동 전이면 건너뛰기)

**화면**: "이미지 생성" 버튼 (mock 또는 실제 provider)

**왜 필요한가**: AI로 대표 이미지를 자동 생성하고 싶을 때 사용한다.
**현재 이 프로그램은 실제 AI 이미지 생성을 아직 연결하지 않았으므로**,
이 단계 대신 10단계(Source Setup)에서 이미지를 직접 준비하는 것이
현재의 표준 경로다.

## 10단계. 대표 이미지 Source 설정 (Step 1)

**화면**: article 상세 페이지 "Step 1. 대표 이미지 Source 설정" 섹션.
세 가지 방법 중 하나를 고른다.

- **A. 로컬 이미지 업로드**: 내 컴퓨터의 이미지 파일 선택 →
  "대표 이미지 파일 저장" (jpg/jpeg/png/webp, 최대 5MB)
- **B. 인터넷 이미지 URL 입력**: 이미지 URL 입력 → "이미지 URL 저장"
  (http/https만 허용, 사용 권한이 있는 이미지만 사용할 것)
- **C. 기존 WordPress media id 입력**: 이미 WordPress Media
  Library에 있는 이미지의 media id 입력 → "기존 media id 저장"
  (이 경우 다음 단계의 업로드를 건너뛴다)

**왜 필요한가**: AI 이미지 생성이 아직 연결되지 않았으므로, 사람이
직접 이미지를 지정해야 한다. 대표 이미지가 없으면(특히 수익형
블로그에서) Publish Quality Gate가 이를 문제로 판정하고, 최종적으로는
Public Publish 자체가 차단된다. **저작권 주의**: 뉴스 기사, 포털, 타인의
블로그에서 가져온 출처 불명확한 이미지는 사용하면 안 된다.

## 11단계. WordPress 연결 테스트

**화면**: "WordPress 연결 테스트" 버튼

**왜 필요한가**: 실제로 글을 올리기 전에, `.env.local`에 설정한
WordPress 주소/계정/Application Password가 올바른지 미리 확인한다.
이 확인 없이 바로 초안 생성을 시도하면 인증 오류의 원인을 찾기
어려울 수 있다.

## 12단계. WordPress 초안 생성

**화면**: "WordPress 초안 생성" 버튼

**왜 필요한가**: 실제 WordPress 사이트에 글을 만드는 첫 단계다. 이때
**post 상태는 항상 `draft`(임시글)로 고정**되며, 아무리 이 버튼을 눌러도
글이 공개되지 않는다. 이미 만들어진 초안이 있으면 중복 생성하지 않고
"이미 생성되어 있습니다"라고 알려준다(중복 글 방지). 이 시점에 대표
이미지 media id가 이미 있으면 자동으로 함께 연결된다.

## 13단계. WordPress Media Upload (Step 2)

**화면**: "WordPress 이미지 업로드 준비" → "업로드 dry-run 확인" →
"WordPress 이미지 업로드 테스트"

**왜 필요한가**: 10단계에서 지정한 이미지 source(로컬 파일/외부 URL)를
실제로 WordPress Media Library에 업로드해서 media id를 발급받는
단계다. (10단계에서 기존 media id를 지정했다면 이 단계는 자동으로
건너뛴다.) dry-run 확인을 먼저 하면 실제로 무엇이 전송될지 미리
점검할 수 있다.

## 14단계. Featured Media Attach (Step 3)

**화면**: "대표 이미지 초안 글에 연결" 버튼

**왜 필요한가**: 13단계에서 발급받은 media id는 아직 "라이브러리에
있는 이미지"일 뿐, 특정 글의 대표 이미지로 지정된 것은 아니다. 이
단계가 그 media를 실제로 12단계에서 만든 draft post에 연결한다. media
id가 없거나 draft가 없으면 버튼이 비활성화되고 안내 문구가 뜬다.

## 15단계. SEO Plugin 실제 반영

**화면**: "SEO plugin metadata 실제 반영 테스트" 또는 "Rank Math custom
endpoint로 SEO 반영" 버튼

**왜 필요한가**: 7단계에서 준비만 해둔 SEO 값(제목/설명/키워드)을 실제
WordPress 글에 기록하는 단계다. Rank Math 같은 plugin은 표준 API로는
값이 반영되지 않는 경우가 있어, 전용 custom endpoint를 통해 직접
저장한다. 이 단계까지 마쳐야 실제 검색엔진에 최적화된 정보가 반영된
글이 된다.

## 16단계. Final Draft Payload Review

**화면**: "Final draft payload 검토 실행" 버튼

**왜 필요한가**: 지금까지의 모든 단계(카테고리/태그/이미지 연결/SEO/
출처/광고 슬롯)가 실제로 draft에 정상 반영됐는지 재점검하는 단계다.
각 단계는 성공했다고 나왔어도, 여러 단계를 거치는 동안 놓친 부분이
없는지 마지막으로 한 번 더 종합 확인한다.

## 17단계. Publish Quality Gate

**화면**: "Publish Quality Gate 실행" 버튼 → 28개 항목 체크리스트와
점수(0~100) 표시

**왜 필요한가**: 이 프로그램에서 가장 중요한 검증 단계다. 제목/본문/
출처/SEO/이미지/광고 슬롯뿐 아니라 **콘텐츠 안전성**(광고 클릭 유도
문구, 근거 없는 단정 표현, 개인정보 노출, 저작권 위험 등)까지 종합
점검해 `ready_to_publish`/`needs_revision`/`blocked` 중 하나로 판정한다.
여기서 `ready_to_publish`가 되지 않으면 다음 단계(승인)로 넘어갈 수
없다.

## 18단계. Human Approval Before Public Publish

**화면**: "공개 게시 승인" 버튼 (Quality Gate가 `ready_to_publish`이고
WordPress draft가 있어야 활성화됨)

**왜 필요한가**: 아무리 자동 검증을 통과해도, **실제 공개는 반드시
사람이 마지막으로 확인하고 버튼을 눌러야만** 진행되도록 만든 안전장치다.
이 단계는 승인 "상태"만 저장할 뿐 아직 실제로 글을 공개하지 않는다.
승인을 잘못 눌렀다면 "공개 게시 승인 취소" 버튼으로 되돌릴 수 있다.

## 19단계. WordPress 공개 게시 테스트

**화면**: "WordPress 공개 게시 테스트 실행 (실제 공개 게시)" 버튼 →
클릭 시 "이 작업은 WordPress 글을 실제 공개 상태로 변경합니다.
계속할까요?" 확인창

**왜 필요한가**: 이 버튼을 누르는 순간 WordPress의 실제 글 상태가
`draft → publish`로 바뀌어 **누구나 볼 수 있게 된다**. 그래서 5중
안전장치(Quality Gate 통과 + 승인 완료 + media 연결 + WordPress draft
존재 + 확인창)를 모두 통과해야만 실행되며, 여러 글을 한 번에 공개하는
기능은 의도적으로 만들지 않았다(실수로 여러 글이 한꺼번에 공개되는
사고를 막기 위함). 이미 공개된 글은 다시 눌러도 중복 공개되지 않는다.

## 20단계. WordPress 관리자에서 최종 확인

**왜 필요한가**: 이 프로그램의 화면과 실제 WordPress 사이트는 별개의
시스템이다. 프로그램 화면에서 "성공"이라고 나와도, 실제 워드프레스
관리자 화면에서 제목/본문/카테고리/태그/대표 이미지/SEO 정보가 모두
의도한 대로 반영됐는지 눈으로 직접 확인하는 것이 마지막 안전장치다.

---

## 자주 헷갈리는 부분

- **"이미 생성되어 있습니다"인데 화면에 경고가 뜬다** → 화면을 새로고침
  해보세요. 다른 단계(Quality Gate, 승인 등)의 로그가 많이 쌓이면
  최신 목록에서 오래된 WordPress 기록이 밀려 보일 수 있었던 문제는
  수정되었습니다.
- **Quality Gate는 통과(pass)인데 공개 게시가 안 눌러진다** →
  Quality Gate의 "이미지 준비됨(warning)"과 "실제 WordPress에 연결
  완료(pass)"는 다른 기준입니다. 공개 게시는 반드시 이미지가 실제로
  WordPress에 업로드·연결까지 완료되어야 허용됩니다.
- **환경변수를 바꿨는데 반영이 안 된다** → `.env.local`을 수정한 뒤에는
  반드시 개발 서버(`npm run dev`)를 재시작해야 한다. 같은 키가 파일에
  중복으로 적혀 있으면 **첫 번째 값**이 적용되므로, 중복 여부도 확인할 것.
